# 大模型、文生图/文生视频与 GPU

这份笔记把语言模型的推理路径、AIGC 的去噪路径，以及 GPU 上为什么一种偏访存、一种偏算力，按同一种语言对齐。公式按现在常见的 Decoder-only 语言模型（RMSNorm、RoPE、SwiGLU、GQA）和潜空间扩散 / 流匹配（DiT）来写。

---

## 1. 原稿里需要改掉的地方

下面这些是原稿中的具体错误，后文按改正后的说法展开。

1. **Q、K 的旋转在投影之后。** 先用 $W_Q, W_K, W_V$ 乘归一化后的向量，得到 $q, k, v$，再只旋转 $q$ 和 $k$。$v$ 不旋转。旋转之前 $q, k$ 还不存在。
2. **注意力分数是当前 $q$ 和各个位置的 $k$ 的点积，不是和过去的 $q$ 比。** 点积结果还要除以 $\sqrt{d_h}$，softmax 之后才是比例 $a$。
3. **加权的 V 包含当前位置自己**，不只是更早的 token。
4. **$y = x + W_O o$ 是注意力之后的第一次残差，此时还没进 FFN。** FFN 的输入是 $\mathrm{RMSNorm}(y)$，不是 $y$ 本身。
5. **第二次残差是 $x_{\text{next}} = y + h$。** $h$ 加回的是 $y$。若加回最初的 $x$，这一层注意力的增量就丢了。
6. **现在常见的 FFN 不是「升一维再降一维」两张矩阵。** SwiGLU 是两套升维（up 和 gate）、逐元素门控，再一套降维。
7. **「维度」有歧义。** $(16,3,5)$ 和 $(15,2,2)$ 的轴数（rank）都是 3，但对不齐的是每一轴的长度。广播规则是从最后一轴往前看，对应轴长度相等或其中一边为 1。16 和 15 对不齐，pad 也不会自动把 16 变成 15，必须改成同一个目标形状再分配新张量。
8. **静态 batch 才把请求 pad 成整齐的 $[N, T]$。** 动态 batch（vLLM、SGLang）用分页 KV cache 和变长注意力，避免把所有序列 pad 到同一长度。客户端线程池只负责把请求送进队列；batch 多大由服务端调度器决定。
9. **没有 chunked prefill 时，一次前向通常要么在做 prefill，要么在做 decode。** 长 prefill 会占住 GPU，decode 要等。chunked prefill 把一段 prefill token 和正在 decode 的 token 放进同一次前向。
10. **TP 的例子是 $512 / 8 = 64$，不是 521。** 每个卡上的中间维是 64。量化块大小 128 时，$64$ 装不下完整的一块，这一维不能按 TP=8 去切。
11. **FFN 不是「因为单向流动所以叫 FFN」。** 它表示每个位置独立做的前馈子层。MLP 是其中一种实现；SwiGLU、MoE 也放在这个子层的位置上。
12. **ALU 不是「整型专用」、IPU 也不是「浮点 ALU」。** ALU 是算术逻辑单元；浮点通常另有 FPU。IPU 在加速器语境里一般指 Graphcore 的 Intelligence Processing Unit，是另一种芯片，不是 ALU 的浮点版本。
13. **文生图从零生成时，初始噪声直接在隐空间采样，不过 VAE 编码器。** VAE 解码器只在去噪结束后跑一次。去噪循环由 DiT 或 U-Net 做。

## 2. 语言模型：从一句话到下一个 token

现代聊天模型几乎都是 **Decoder-only Transformer**，生成方式是自回归：每一步只预测下一个 token 的概率，再把采样到的 token 接回序列。

模型内部没有「先写好整段再一次吐出」的步骤。所谓理解、推理链，都是这些条件概率接出来的：先生成的 token 会改变后面 token 的条件分布。

### 2.1 进网络之前

真正送进网络的通常不是对话框里的那一行，而是按 **chat template** 拼好的字符串：

- 系统提示、工具说明
- 历史轮次（user / assistant）
- 当前用户消息
- 模型规定的特殊符号，例如角色开始、角色结束

模板不属于 Transformer 权重。Qwen、Llama、DeepSeek 的特殊 token 和角色标记各不相同，必须用该模型 tokenizer 自带的 `chat_template` 来拼。手写一套标记，权重对不上，模型行为会乱。

进网络之前还可能有这些步骤，它们不是主模型的一层：

- 上下文超长时截断或摘要
- RAG：检索结果当成普通文本塞进 prompt
- 安全分类：另一套小模型或规则，决定拦不拦

### 2.2 分词

模型读的是 token id，不是汉字或单词。常用 BPE、SentencePiece。一个 token 可能是一个字、一个词，或一个词的碎片；罕见符号会落到字节。

```text
一段话 → chat template → token id 序列 [t0, t1, ..., t_{n-1}]
```

词表大小 $V$ 常见是几万到二十万。特殊 id 包括结束符、填充符、对话边界。分词器和权重必须成对，换一套词表等于换了一种语言。

### 2.3 一次完整前向

```text
token id
  → 嵌入表查行，得到每个位置的 x          # 形状 [n, d]
  → 第 0 层 … 第 L-1 层                    # 每层 Attention + FFN
  → 最后一次 RMSNorm
  → lm_head：d 维 → V 个分数
  → 采样一个 token id
  → detokenize 成可见文字
```

位置信息多数不在嵌入上相加。Llama 一类在每一层注意力内部，对 $q, k$ 做 RoPE。

### 2.4 lm_head

`lm_head` 是最后那个线性层，不是 Transformer 块。最后一层、最后一个位置的隐藏向量 $h$（$d$ 维）乘 $W_{\mathrm{lm}}$（大约 $d \times V$）：

$$
\mathrm{logits} = W_{\mathrm{lm}} h \in \mathbb{R}^{V}
$$

温度 $T$ 之后做 softmax，得到下一个 token 的概率，再按 top-k、top-p 等规则采样。有的模型让 $W_{\mathrm{lm}}$ 和嵌入表共用同一套权重。

logits 还不是字。采样出的 id 交给分词器，才变成 UTF-8 文本。一个汉字可能要好几个 token 才拼得完整，所以流式输出有时会晚半拍。

### 2.5 生成循环是串行的

```text
prefill：提示里的 n 个 token 一起走完所有层 → 预测第 1 个新 token
decode： 这个新 token 再走完所有层 → 预测下一个
         再下一个，直到结束符或长度上限
```

- **层与层串行**：第 3 层的输入是第 2 层的输出。
- **decode 的字与字串行**：没有新 token 的嵌入，下一步无法开始。
- **同一层内部可以并行**：多个头、多个历史位置的点积、prefill 时一句里的多个位置。

下一轮的输入是 **新 token 的嵌入**，不是上一轮最后一层的隐藏向量，也不是层内的 $y$。上一轮留下来的是这个 token id，以及每一层写进 KV cache 的 K、V。

## 3. 批处理

### 3.1 为什么张量必须规整

一个稠密张量是一块连续内存加一个形状。形状 $[N, T, d]$ 表示 $N$ 条序列、每条 $T$ 个位置、每个位置 $d$ 个数，而且 **每条的 $T$ 必须相同**。内存按固定步长跳跃，不存在「第 0 条 100 个 token、第 1 条 7 个 token」却还放在同一个 $[N, T, d]$ 里。

所以静态 batch 把短句用 pad token 补到这批里最长的 $T$，得到整齐的 $[N, T]$，再一起 embedding，变成 $[N, T, d]$。注意力 mask 把 pad 位置盖住，不让它们参与 softmax。代价是 pad 也占用计算和显存。

### 3.2 广播和对不齐的例子

$(16, 3, 5)$ 和 $(15, 2, 2)$ 都是三维张量（轴的个数相同），但每一轴的长度都不同。逐元素相加或拼成一个 batch 时，从最后一轴对齐：

| 轴（从右往左） | 左边 | 右边 | 能否广播 |
|---|---|---|---|
| 最后一轴 | 5 | 2 | 不能，都不是 1 |
| 中间 | 3 | 2 | 不能 |
| 最左 | 16 | 15 | 不能 |

广播只允许「长度相等」或「其中一边是 1（把那一轴复制）」。例如 $(16, 1, 5)$ 可以广播到 $(16, 3, 5)$。16 和 15 无法靠广播对齐。

pad 是另一步：分配一块新形状的内存，把有效数据拷进去，空位填特殊 id。它不会把已有的 16 这一轴变成 15。若两个张量要放进同一次批计算，必须先变成同一个目标形状。

矩阵乘的规则更具体。$(M, K)$ 乘 $(K, N)$ 时，中间那个 $K$ 必须相等，外面的 $M, N$ 可以不同。batch 那几轴才要求相等或可广播。

### 3.3 静态批处理

离线、长度差不多的请求可以这样做：

1. 等齐 $N$ 条请求，或凑满一个时间窗。
2. pad 到同一 $T$，组成 $[N, T]$。
3. 一次前向算完整个 batch。
4. 最短的那条也要等到最长的那条结束才能返回。

GPU 上的大矩阵乘喜欢这种规整形状。浪费来自 pad，以及「快的等慢的」。

### 3.4 动态批处理（continuous batching）

vLLM、SGLang 这类服务不把所有请求 pad 成一个 $[N, T_{\max}]$。

- 请求随时进入等待队列，生成结束的请求随时离开。
- 调度器看队列深度、剩余显存、配置的 token 上限，决定 **这一步** 把哪些请求送进 GPU。
- KV cache 按页（block）分配。每条请求的历史长度可以不同，空页不给短请求预留成一整块 $[T_{\max}]$。
- 真正计算的 token 被打包成「这一步要算的那些行」。变长注意力（FlashAttention 的 `cu_seqlens` 一类）用偏移数组记住每条序列的边界，不要求每条都一样长。

客户端用线程池或异步 HTTP 并发发送，只是让队列里有足够多的请求。 **拼多大的 batch 是服务端决定的。**

Decode 时如果有 $B$ 条请求各生成 1 个 token，线性层左边的行数就是 $B$，不再是 1。$B$ 变大，权重被复用的次数变多，访存压力会被摊薄。

### 3.5 Iteration：一步调度

Iteration 是服务里的一步：挑出这一步要算的 token，做一次完整前向，再把结果写回各条请求。它不是一层 Transformer，也不是某一次矩阵乘。

一个 iteration 里可以有多条请求。Decode 步里，每条正在生成的请求拿出 1 个新 token，100 条就是 100 行，一起乘同一份权重。Prefill 步里，一条长提示自己就有几千行；几条短提示也可以拼进同一次前向。不是「decode 能并行、prefill 不能并行」。

没有 chunked prefill 时，调度器常常把整段 prefill 和 decode 分成不同的 iteration。一次前向只有一个计算图，选中的 token 会一起走完所有层。长 prefill 有几千行，若和正在吐字的请求绑在同一步，那些 decode 就要等它结束，用户看到的间隔会突然变长。

### 3.6 Prefill 和 decode 能不能同一次前向

两条路径可以放进同一次前向，只是不额外调度时通常不这么做。长 prompt 的 prefill 可能独占 GPU 几百毫秒，正在一个字一个字吐的请求只好等。

**Chunked prefill** 把长 prompt 切成小块，例如每步只算 512 个 prefill token，并和正在 decode 的那些 token 打进同一次前向。Decode 不用等整段提示算完。代价是实现更复杂，prefill 总时间不一定变短，但 decode 的间隔更稳。

SGLang 还有 radix cache / prefix cache：相同前缀（系统提示、few-shot）的 KV 可以在请求之间复用，不必每次从头 prefill。

## 4. 一层 Transformer

一层的输入、输出都是隐藏向量，维度都是 $d$。一层不产生文字。文字只在 **全部层走完、lm_head 之后** 出现。

以一个 token 在 decode 时走过某一层为例。历史 token 的 K、V 已经在 **这一层** 的 cache 里。

```text
x
  → RMSNorm → x_norm                         原始 x 留下
  → q, k, v = W_Q x_norm, W_K x_norm, W_V x_norm
  → 只对 q、k 做 RoPE
  → 把本位置的 k、v 写入这一层的 KV cache
  → 分数 s_j = (q · k_j) / sqrt(d_h)         j = 0 … t，含自己
  → a = softmax(s)
  → o = Σ a_j v_j                            各头拼回 d 维
  → y = x + W_O o                            第一次残差
  → h = FFN(RMSNorm(y))                      FFN 不看未经 Norm 的 y
  → x_next = y + h                           第二次残差
  → x_next 进入下一层
```

### 4.1 注意力在算什么

$q$ 是「我现在要找什么」，$k$ 是「这个位置的检索标签」，$v$ 是「被抄走的内容」。

当前 $q$ 和每一个 $k_j$ 的点积互不依赖，GPU 上是一次矩阵乘向量：$K$ 的形状是 $(\text{历史长度}, d_h)$，$q$ 的形状是 $(d_h,)$，乘积是每个位置一个分数。Softmax 要等这一排分数到齐才能做分母，这是一次汇总，不是从左到右串行点积。

加权和

$$
o = \sum_j a_j v_j
$$

是给 **当前位置新造的向量**。cache 里的 $v_j$ 一个数都不改，以前位置已经算完的输出也不改。$o$ 和 $v$ 是两份数据。

多头的实现：一个大的 $W_Q$ 乘一次，再按头切开。大矩阵就是每头一块小矩阵横着拼起来，每头的权重不同。效果等于每个头各有一套小 $W_Q$。K、V 同理。GQA 时 $W_K, W_V$ 更窄，因为 KV 头更少。

### 4.2 每一层的 KV 不共用

同一个 token 在第 0 层和第 3 层各有一套 K、V。输入 $x$ 不同，$W_K, W_V$ 也不同。

当前 token 走到第 3 层时，只用第 3 层 cache 里各历史位置的 K、V。Q 一般不进 cache，打完分就丢掉。

### 4.3 Prefill 和 decode

**Prefill。** 提示中每个 token 都查嵌入，并排走完每一层。每个位置都写出自己在每一层的 K、V。用来预测第一个新字的，只有 **最后一个位置** 走完最后一层之后的向量。前面的位置在推理时不再接 lm_head。

**Decode。** 只有最新这个 token 查嵌入，从第 0 层走到最后一层。它在每一层用自己的 $q$ 去读该层 cache。走完后 lm_head 预测再下一个 token。这个新 token 下一轮再走一遍所有层。

Prefill 时同一层的多个位置一起乘权重，矩阵很「厚」，常常吃满算力。Decode 每次每个请求只有 1 个新 token（batch 大时是 $B$ 行），权重搬进来复用次数少，常常吃满显存带宽。

## 5. 头、GQA、MLA

### 5.1 头是什么

隐藏向量有 $d$ 个数，例如 4096。注意力不把 4096 维做一次大点积，而是切成多路，每路一个小的 $q, k, v$。每一路叫一个头。

$d = 32 \times 128$ 时，有 32 个头，每头 128 维。头 0 的 $q$ 只和头 0 的 $k, v$ 算。各头同时算，输出拼回 4096，再乘 $W_O$ 混合。

不同头可以学会不同关系：相邻词、句首主语、否定范围。这是训练结果，不是人工指定第几头干什么。

### 5.2 KV 头可以更少

K、V 要按层、按 token 存进 cache。头越多，cache 越大。

| 名称 | Q 头 | KV 头 | 关系 |
|---|---|---|---|
| MHA | 32 | 32 | 一一对应 |
| GQA | 32 | 8 | 每 4 个 Q 头共用 1 个 KV 头 |
| MQA | 32 | 1 | 所有 Q 头共用一套 K、V |

共用的是 K、V，不是 Q。两个 Q 头的问题可以不同，检索标签和抄的内容相同。

### 5.3 MLA（Multi-head Latent Attention）

MLA 是 DeepSeek-V2 一类模型用来缩小 KV cache 的做法。GQA 是「少存几份头」；MLA 是「先把 K、V 压成一条低维向量再存」。

概念上，每个 token 在某一层：

1. 用一个降维矩阵把隐藏向量压成较短的潜向量 $c$（例如几百维），**cache 里主要存 $c$**。
2. 需要 K、V 时，再用升维矩阵把 $c$ 变成各头的 $k, v$。
3. RoPE 不能直接做进这个低秩压缩里（旋转和那次矩阵乘对不齐），所以另外缓存一条很短的、已经旋转过的位置键，和压缩向量一起参与点积。

推理时可以把升维矩阵吸收进 Q 的投影和输出投影，注意力直接在短的 $c$ 上做，不必先把所有头的 K、V 展开到显存里。cache 的大头从「层数 × KV 头数 × 头维 × 序列长度」变成「层数 × 压缩维 × 序列长度」，再加上那条很短的位置键。

注意力的含义不变：仍然是 $q$ 和历史键做分数，再对值加权。变的是键和值在显存里的存法。

## 6. 残差、RMSNorm、FFN、MoE

### 6.1 残差

$$
y = x + \Delta_{\mathrm{attn}}, \qquad x_{\mathrm{next}} = y + \Delta_{\mathrm{ffn}}
$$

每一层往向量上 **加一块增量**。增量接近 0 时，这一层近似原样通过。浅层写下的信息还在，深层继续添。训练时梯度也能沿着加法回到前面的层。

### 6.2 RMSNorm

把一排数的整体幅度拉回稳定范围，方向保留：

$$
\mathrm{RMS}(x) = \sqrt{\frac{1}{d}\sum_i x_i^2}, \qquad
x_{\mathrm{norm}} = \frac{x}{\mathrm{RMS}(x)}\odot \gamma
$$

$\gamma$ 是这一层可学习的 $d$ 个数。它放在注意力前、FFN 前。进 $W_Q$ 和 FFN 的是归一化后的向量；加残差用的是归一化前的向量。

幅度不管住时，$q\cdot k$ 会过大或过小，softmax 会过尖或过平。

### 6.3 FFN 和 MLP

FFN 是子层的名字：每个位置单独做变换，不读别的位置。同一层所有位置共用一套权重。

MLP（多层感知机）是一种实现：线性层、非线性、再线性层。语言模型里这个子层的常见实现是 SwiGLU：

$$
u = W_{\mathrm{up}} y_{\mathrm{norm}}, \quad
g = W_{\mathrm{gate}} y_{\mathrm{norm}}
$$

$$
h_{\mathrm{mid}} = \mathrm{SiLU}(g) \odot u, \quad
h = W_{\mathrm{down}} h_{\mathrm{mid}}
$$

$d = 4096$ 时中间维常常是一万多。中间维只活在 FFN 内部，$h$ 必须回到 $d$ 维才能和 $y$ 相加。

稠密模型里，这个 FFN 就是一个 MLP。MoE 把这一个 MLP 换成路由器加上多个 MLP。RMSNorm 是入口，不算在 MLP 的三套矩阵里。

MLP 不负责看别的词，那是注意力刚做完的事。注意力结束时，当前位置的向量里主要是抄来的原料。比如「法国的首都是」，最后这个位置已经通过注意力带上了「法国」和「首都」，但「下一个词是巴黎」还没写上。升维矩阵相当于一大批检测器，每个看一种组合；门控把这次无关的检测器乘到接近 0；降维把打开的结果写回原来的维度，例如往向量里加上「巴黎」那个方向。全句共用这一套规则，每个位置按自己的向量各算一遍。

只有加权平均、没有这次逐位置的非线性，很多层叠起来也很难表达「两个条件同时成立才写入某个结论」。所以一层分成两截：注意力决定抄谁，FFN 决定抄完变成什么。参数大多在这三张矩阵上，一层里的访存量也常常是这里最大。

### 6.4 MoE

MoE 只替换 FFN 里的 MLP，不改前面的注意力。同一层的 $W_Q$、$W_K$、$W_V$、$W_O$，以及 GQA 或 MLA，对所有 token 是同一套。选了不同专家，不会换成另一种注意力，也仍然读同一份 KV cache。

每个专家是一套自己的 `W_up`、`W_gate`、`W_down`。路由器看当前向量，在 $E$ 个专家里选 top-$k$ 个。一个 token 激活几个，就把那几个 MLP 各算一遍，再按路由权重加总，得到这一层唯一的增量 $h$。下一层还是一条向量，不会变成 $k$ 条。没被选中的专家这次不乘。同一批里选中同一个专家的 token，会并成多行一起乘这个专家的矩阵。

还有一种 **共享专家**：每个 token 都走，用来承担所有 token 都需要的那部分变换。被路由的专家承担分化开的那部分。

示例（按一组 35B 量级、激活约 3B 的配置）：

| 参数 | 值 | 含义 |
|---|---|---|
| `num_experts` | 256 | 可被路由的专家个数 |
| `num_experts_per_tok` | 8 | 每个 token 选 8 个 |
| `moe_intermediate_size` | 512 | 每个被路由专家的 FFN 中间维 |
| `shared_expert_intermediate_size` | 512 | 共享专家的中间维 |

一个 token 的 FFN 计算量大约是「8 个小专家 + 1 个共享专家」，不是 256 个全算。参数量按 256 个专家存，所以模型文件大、单 token 计算量小。专家要放在哪些卡上，是专家并行（EP）的问题；负载不均时，有的专家很忙，有的几乎空闲。

## 7. 各种「维度」分别量什么

维度首先是 **一排里有几个数**，用来让矩阵乘的边对得齐。

| 名字 | 量的是什么 |
|---|---|
| 隐藏维 $d$ | 层与层之间每个 token 的那一排数。嵌入、每层输出、残差都是它 |
| 头数 × 头维 | $d$ 在注意力里怎么切开。点积的两边必须都是头维 |
| KV 头数 | 这一层 K、V 切成几路 |
| FFN 中间维 | 升维之后、降维之前的长度 |
| MoE 专家中间维 | 单个专家内部的升维长度，通常比稠密 FFN 小 |
| 词表大小 $V$ | lm_head 输出有多少个分数，不是隐藏向量的长度 |
| 序列长度 | 有多少个 token。是表的行数 |
| batch | 同时算几条互不相干的序列 |

RNN 的「512 维」和 Transformer 的「4096 维」是同一类数：表示一个位置（RNN 里是那条共用状态）用多少个小数。RNN 把整句挤进同一条状态里传；Transformer 让每个 token 自己留一条 $d$ 维向量，再用注意力去读别人。

$d$ 翻倍时，$d \times d$ 的权重约变成 4 倍。头数通常跟着增加，使每头仍在 128 左右。

## 8. 量化、TP 与 blockwise

### 8.1 量化

权重从 FP16/BF16 换成 INT8、FP8 或 INT4，每个数占用的字节变少，搬权重的时间下降。计算前要按 scale 把低精度数还原到内核能乘的范围，或使用直接吃低精度的 Tensor Core。

- **per-tensor：** 整张矩阵一个 scale。
- **per-channel：** 每一行或每一列一个 scale。
- **group-wise：** 沿求和的那一维，每 128 个数一个 scale。
- **block-wise：** 两个方向都分块，例如 $128\times128$ 一块一个 scale。

### 8.2 张量并行 TP

TP 把 **一层的权重** 切开，放到多张卡上。每张卡只算自己那一块，再通信拼结果。

FFN 中间维 512、TP=8 时，每张卡上的中间维是 $512/8 = 64$。每张卡做自己的那 64 维升维，降维之后要 AllReduce，把部分和加起来，得到完整的 $d$ 维输出。

注意力的头也可以按头切开：每张卡拿若干个头，算完再拼接。

TP 的代价是每层至少一次集合通信。卡间带宽（NVLink 相对 PCIe）直接决定能不能把通信藏住。

### 8.3 为什么 64 对不齐 128 的 block

Block size 切分是量化时把权重划成小块，一块共用一个 scale。块太大，块内的大数会把小数四舍五入没；每个数一个 scale，则 scale 本身几乎和原矩阵一样大。128 是常见边长。

两个方向都分块时，$512 \times 4096$ 的矩阵划成 $128 \times 128$ 的格子：512 这边 4 行，4096 这边 32 列。每一格里是低精度权重，外加一个 scale。做矩阵乘时按块用自己的 scale 还原。group-wise 只沿求和的那一维每 128 个数一个 scale，对齐要求相同。

block size = 128 表示一块量化格子在某一维上占 128 个权重。TP 把矩阵沿这一维切开时，**每张卡分到的长度必须是 128 的整数倍**，格子才不会被切到两张卡上。

TP=4、中间维 512 时，每卡 128 行，刚好一块，scale 全在这张卡上。TP=8 时每卡只剩 64 行，原来的第一块 128 行被卡 0 和卡 1 各拿一半，两边都凑不齐同一个 scale，这种量化就不能按 TP=8 切。专家并行不切开这 512 行，整个专家和它的块都在同一张卡上，没有这个问题。只有再对同一个专家做 TP 时才要对齐 block size。

512 能被 128 整除，整模可以做 block-wise。TP=8 之后每卡只剩 64。64 小于 128，一块格子放不进一张卡。因此这种量化格式在这个中间维上不支持 TP=8。TP=4 时每卡 128，刚好一块，可以对齐；TP=2 时每卡 256，是两块，也可以。

这不是「64 无法做矩阵乘」，而是「这种量化分块方式和这种切法不兼容」。

### 8.4 DP、EP、PP

| 名称 | 切的是什么 | 通信大致是什么 |
|---|---|---|
| 数据并行 DP | 每张卡一份完整权重，batch 拆开 | 训练时同步梯度；推理时各卡独立出结果 |
| 张量并行 TP | 一层权重切开 | 每层 AllReduce 或 AllGather |
| 专家并行 EP | 不同专家放在不同卡 | token 按路由结果发到对应卡，再发回来 |
| 流水并行 PP | 不同层放在不同卡 | 激活沿流水线传递 |

MoE 模型常常 TP（切注意力和共享专家）和 EP（把 256 个专家摊到多卡）一起用。DP 用来同时服务多份流量，或在训练时扩大 batch。

## 9. 文生图、文生视频

### 9.1 三个模型，一段循环

主流路径是潜空间里的扩散或流匹配，不是一个字一个字吐像素。

| 模型 | 何时运行 | 作用 |
|---|---|---|
| 文本编码器（CLIP 文本塔、T5 等 Transformer） | 通常一次 | 把提示词变成一串条件向量 |
| 去噪网络（U-Net 或 DiT） | 每一步都跑 | 看当前隐图像、时间步、文字，预测修正量 |
| VAE 解码器 | 最后一次 | 把干净的隐表示变成像素 |

从零生成的顺序：

```text
在隐空间按标准正态采样 z_T          # 例如 4×64×64，不过 VAE 编码器
重复 十几到几十步：
    DiT/U-Net 预测噪声 ε 或速度
    调度器把 z 更新得更干净一点
VAE 解码器：z_0 → 像素图
```

负向提示会再编码一次。同一步常常算「有文字」和「空文本」两个修正，再按 guidance scale 拉开：

$$
\epsilon = \epsilon_{\mathrm{空}} + s(\epsilon_{\mathrm{提示}} - \epsilon_{\mathrm{空}})
$$

### 9.2 VAE 和隐空间

VAE 是单独的小模型，有编码器和解码器。

- 编码器：像素 → 隐空间里的一个分布，再抽样得到 $z$。
- 解码器：$z$ → 像素。
- 训练时既要重建得像原图，又把隐分布往标准正态上拉，这样从随机噪声出发解码才不会落在「解码器没见过的角落」。

文生图的 $z$ 通常不是一个 4096 维的点，而是一张缩小的多通道图，例如 $64\times64\times4$。位置还在，细节被压进每个格子的几个数里。

**从零生成不跑编码器。** 噪声按 $z$ 的形状直接抽取。编码器用在训练（把真实图压进隐空间再加噪）和图生图（先编码已有的图，再加噪、再去噪）。

视频用 3D VAE：时间也被压缩。去噪的是一块「时间 × 高 × 宽 × 通道」的特征，最后解码成一帧帧像素。

### 9.3 三种容易混的「内部的数」

| | 是什么 | 谁产生 | 下一步还用不用 |
|---|---|---|---|
| 语言模型 / 文本编码器 / DiT 的 hidden state | 某个 token 在某一层的 $x$ | 这一次前向 | 只传给下一层；前向结束就丢掉 |
| 图像隐变量 $z$ | 整张图的压缩表示 | 随机采样，或 VAE 编码器 | 去噪的每一步都在改它；最后交给解码器 |
| lm_head 的 logits | 词表上的分数 | 最后隐藏向量乘 $W_{\mathrm{lm}}$ | 采样出一个 id，再查嵌入 |

语言模型的主角是 hidden state：最后一层最后一个位置乘 lm_head 得到下一个字。文生图的主角是 $z$：DiT 的 hidden state 只用来算出「$z$ 该怎么改」。

### 9.4 从纯噪声到干净图

$z_T$ 的每个数独立随机，没有物体。一个去噪步：

1. 把 $z_t$ 切成 patch，加上时间步和文字条件，走完 DiT 的所有层。层与层串行；同一层里所有 patch 并行，而且互相看得见。
2. 每个 patch 的最后隐藏向量乘一个线性层，拼成和 $z_t$ 同形状的修正表。扩散里这是估计的噪声；流匹配里这是走向干净图的速度。这里像 lm_head 的地方只有「hidden state 乘矩阵得到这一步的输出」。输出不是词表概率。
3. 调度器用 $z_t$ 和这张修正表走一小步，得到 $z_{t-1}$。一步不走完，是因为噪声很大时网络只能看清粗布局。
4. 丢掉 DiT 的 hidden state。下一步的输入是新的 $z$，时间步也变了，所有层重新算。没有 KV cache 可以复用，因为条件（噪声水平）已经变了。

前几步出现大块明暗和构图，中间几步出现物体和颜色，后几步改边缘和纹理。结束后 $z_0$ 仍不是像素，VAE 解码器才把它放大成图。

文生视频同一套。初始噪声的形状带时间维；每一步修正整段视频的隐表示，不是先画完第 1 帧再画第 2 帧。

### 9.5 DiT 的一层

DiT 的一层仍然是归一化、注意力、残差、FFN、残差。和语言模型一层的差别：

1. **输入是所有图像块**，不是「当前 1 个 token」。
2. **注意力是双向的。** 每一块的 $q$ 和所有块的 $k$ 做点积，没有因果掩码。
3. **时间步变成旋钮。** 条件向量 $c$ 生成缩放 $\gamma$、平移 $\beta$、门控 $\alpha$。归一化之后做 $(1+\gamma)\odot \mathrm{Norm}(x)+\beta$。残差是 $x + \alpha \odot \Delta$。噪声多和噪声少时，同一层可以少写或多写增量。
4. **文字是条件。** 交叉注意力时，图像 $q$ 去看文字的 $k, v$。联合注意力时，文字 token 和图像 token 接在一起做同一次注意力。
5. **位置** 可以在进第一层前加固定正弦编码（原版 DiT），也可以在 $q, k$ 上做 RoPE（现在的文生图、文生视频更常见）。
6. 一层的输出仍是隐藏向量。修正表要等所有层走完，由最后的线性层拼出来。

原版 DiT 的 FFN 多是「升维 → GELU → 降维」。新模型可以换成 SwiGLU，也可以在部分层用 MoE。

早期 Stable Diffusion 的去噪网络是 U-Net：卷积降采样再升采样，文字用交叉注意力注入。现在的高画质模型更多换成 DiT。也存在把图变成离散视觉 token、再用因果 Transformer 逐个预测的路线；那一条才有和语言模型一样的 prefill、decode 和 KV cache。当前常见产品走的是去噪循环。

### 9.6 和语言模型对照

| | 语言模型 | 文生图 / 文生视频 |
|---|---|---|
| 生成物 | 离散 token | 连续隐图像或隐视频，最后解码成像素 |
| 主循环 | 每得到 1 个 token 走一遍网络 | 同一张 $z$ 按噪声步走很多遍 |
| 一次前向的输出 | 下一个 token 的 logits | 与 $z$ 同形状的噪声或速度 |
| 注意力可见范围 | 只能看左边 | 图像块之间可以互看 |
| 历史怎么留 | KV cache，旧 token 不重算 | 每步整网重算 |
| 文字 | 就是被生成的内容 | 是条件 |
| 初始输入 | prompt 的 token 嵌入 | 隐空间里的随机数 |
| 典型瓶颈 | decode、小 batch 时搬权重，偏访存 | 每步成千上万个 patch 一起乘权重，偏算力 |

## 10. GPU：算力、带宽和芯片上的位置

### 10.1 一次计算卡在哪里

GPU 同时有算力上限（每秒多少次乘加）和带宽上限（每秒从显存读多少字节）。

$$
\text{算术强度} = \frac{\text{计算量}}{\text{要从显存读的字节}}
$$

强度低于「峰值算力 / 显存带宽」时，算力在等数据，是 **访存 bound**。强度高于这个拐点时，是 **算力 bound**。

语言模型 decode、batch 很小时，一个大矩阵只乘 1 个（或很少几个）向量。权重读一次几乎只服务一行，强度接近每字节 1 次运算，所以卡在带宽。KV cache 越长，每步还要多读历史 K、V。

DiT 的一步把同一份权重复用到所有图像块上。块越多，同一份权重对应的运算越多，强度越过拐点，卡在 Tensor Core。语言模型的 prefill（一整段 prompt 一起乘）也会往算力这边靠。

量化、GQA、MLA、加大 decode batch，都是在少搬数据或提高权重复用。减少去噪步数、缩小分辨率，是在少算。

### 10.2 CUDA Core 和 Tensor Core

- **CUDA Core：** 通用浮点/整数运算单元，适合逐元素运算、归约、控制流多的核。矩阵乘也能做，但吞吐远低于专用单元。
- **Tensor Core：** 只做小块矩阵乘加（例如一种 tile 的 $D = A B + C$），一次吞吐一大块乘加。GEMM、注意力里的 $QK^\top$ 和 $PV$，主要跑在这里。低精度（FP16、BF16、FP8、INT8）是它的主场。

RMSNorm、softmax、SiLU、残差相加这类逐元素或小归约，更接近 CUDA Core 或专用的内存带宽核。一层里的时间经常仍由那些大矩阵乘决定。

### 10.3 SIMT 和 SIMD

- **SIMT（Single Instruction, Multiple Threads）：** NVIDIA 的执行方式。一个 warp（通常 32 个线程）共用一条指令。每个线程有自己的寄存器和自己的那份数据，也可以有自己的分支；分支不一致时，硬件把两边串行执行并掩掉不该执行的线程。注意力里「每个线程负责一个位置的一部分点积」就是这种模型。
- **SIMD（Single Instruction, Multiple Data）：** 一条指令在 **一个线程** 的向量寄存器上同时处理多个数据，例如 CPU 的 AVX 一次算 8 个 float。线程没有拆成 8 个，数据被打包在一条指令里。

两者都是「一条指令覆盖多个数据」。SIMT 的并行单位是线程，SIMD 的并行单位是一个线程内部的数据通道。

### 10.4 ASIC、ALU、FPU、IPU

- **ASIC：** 为一种用途做的专用芯片。一个只跑固定解码的芯片是 ASIC。GPU 是可编程的，一般不叫 ASIC；里面的 Tensor Core、视频编解码器可以看成专用电路块。
- **ALU：** 算术逻辑单元，做整数加减、移位、与或非。它不是「整颗芯片」，是执行单元里的一块。
- **FPU：** 浮点运算单元。浮点加减乘在这里，不在传统 ALU 的定义里。CUDA Core 里同时有整数和浮点数据通路。
- **IPU：** 在加速器产品里通常指 Graphcore 的 Intelligence Processing Unit，用大量片上 SRAM 和很多小核做图计算，是和 GPU 并列的另一种架构。它不是「浮点版 ALU」。芯片设计里的 IP 又是另一回事，指可以授权集成的电路模块（IP 核）。

### 10.5 存储从远到近

计算只能发生在寄存器里。数据从远到近大致是：

| 位置 | 谁共享 | 容量级 | 作用 |
|---|---|---|---|
| HBM / GDDR（显存，DRAM） | 整卡 | 几十 GB | 放权重、KV cache、激活。带宽高，延迟仍远高于片上 |
| L2 cache | 整颗 GPU | 几十 MB | 最近用过的显存数据的缓存 |
| L1 / shared memory | 一个 SM | 百 KB 级 | 核函数主动搬进来的块，GEMM tile 放这里 |
| 寄存器 | 一个线程；寄存器堆属于 SM | 每线程几十到几百个 | 正在参与运算的数 |

「把 $W_Q$ 从显存搬进来」指的是：权重平时在 HBM，内核把一小块搬进 shared memory 和寄存器，乘完这一块就可以丢掉。HBM 里的原件还在。下一个 token 若还要这张表，就再搬一次。

KV cache 也在 HBM，是另一块区域，存的是已经算好的 K、V（或 MLA 的压缩向量），不是权重。注意力内核从这里把历史 K、V 读进 SM 去做点积。

权重进不了「KV cache」这个软件结构，也进不了一整份模型那么大的寄存器堆。芯片上的缓存只是搬运时的工作台。

### 10.6 卡怎么插、怎么互联

- **PCIe：** 一种串行总线协议，也常常指主板上的插槽形态。CPU 和 GPU 之间传数据、加载模型，多数走 PCIe。带宽相对 NVLink 低。说「一张 PCIe 卡」时，指的是插在这个槽上的板卡形态。
- **SXM：** NVIDIA 使用的一种模组形态，供电和散热按高功耗设计，GPU 之间走 NVLink，不是普通 PCIe 插槽上的那块板。
- **OAM（OCP Accelerator Module）：** 开放计算项目规定的 **加速卡物理模组** 标准：外形、供电、散热器接口。它规定的是模块长什么样，不规定一定用 NVLink。计算走什么协议要看具体芯片。
- **NVLink：** NVIDIA GPU 之间的高速互联。TP 的 AllReduce 希望走它，而不是绕回 CPU 的 PCIe。
- **NVSwitch：** 把多张 GPU 的 NVLink 接成可同时两两通信的交换芯片。没有它，卡多了之后不是任意两张都能以满带宽直接相连。

形态（PCIe 板、SXM、OAM）和协议（PCIe、NVLink）是两套词。一张卡可以是 OAM 外形，同时用 PCIe 连主机；NVIDIA 的 SXM 模组则通常用 NVLink 连其他 GPU。

## 11. 一条对照用的最小流程

**语言模型生成一个新字**

```text
新 token id → 嵌入 → x
for 每一层:
    x = 层(x, 这一层的 KV cache)     # 只把本层新的 k,v 追加进 cache
最后 RMSNorm → lm_head → 采样 id → 显示
```

**文生图生成一张图**

```text
文字 → 文本编码器 → 条件向量          # 一次
z = 隐空间随机噪声                     # 不过 VAE 编码器
for 每个噪声步 t:
    修正 = DiT 或 U-Net(z, t, 条件)    # 所有 patch 一起，整网重算
    z = 调度器(z, 修正)
像素 = VAE 解码器(z)                   # 一次
```

**文生视频** 与文生图相同，$z$ 和 DiT 的 token 多一个时间维，每一步更新整段视频的隐表示。

## 12. 集合通信

下面用 4 张卡。A2A 结束时每张卡拿到的是来自其他卡的**不同**数据块，不是同一份的拷贝。

### 12.1 All-to-All

每张卡按目的地把自己的数据切成内容不同的几份。卡 0 的四段分别是「给卡 0、给卡 1、给卡 2、给卡 3」的，四段不一样：

```text
卡0：A0 A1 A2 A3
卡1：B0 B1 B2 B3
卡2：C0 C1 C2 C3
卡3：D0 D1 D2 D3
```

卡 0 发给卡 1 的只有 A1，发给卡 2 的只有 A2。结束后：

```text
卡0：A0 B0 C0 D0
卡1：A1 B1 C1 D1
卡2：A2 B2 C2 D2
卡3：A3 B3 C3 D3
```

四行互不相同，也不会再拼成每张卡都一样的大块。专家并行的 dispatch / combine 就是这个：卡 0 上的专家只收到选中它的 token。

### 12.2 AllGather

每张卡只有自己的一段，发给别人的是**这一整段的拷贝**，不是切成不同的几截。

```text
开始：卡0=A  卡1=B  卡2=C  卡3=D
结束：四张卡都是 [A, B, C, D]
```

张量并行里每张卡只有完整向量的几行、下一步又需要完整向量时，用 AllGather。

### 12.3 AllReduce

每张卡上是同一形状的数，按元素相加。结束后每张卡都是同一份和，原来各卡自己的那份不单独留下。

```text
卡0：1  2  3  4
卡1：10 20 30 40
卡2：5  5  5  5
卡3：4  3  2  1
结束后每张卡都是：20 30 40 50
```

TP 里每张卡的 FFN 只算出输出的一部分和，AllReduce 把这些部分和加完，每张卡都有完整的 $d$ 维，才能进下一层。

### 12.4 其他几个

| 通信 | 结束时每张卡有什么 |
|---|---|
| All-to-All | 来自其他卡的不同数据块，各卡手里不一样 |
| AllGather | 各卡原来的数据拼接成的同一份 |
| AllReduce | 按位相加后的同一份和 |
| ReduceScatter | 先相加，每张卡只留下和的一段，各卡留下的段不同 |
| Broadcast | 某一张卡的数据原样复制到所有卡 |
| Send/Recv | 只有收发的那两张卡之间多了一块数据，其余卡不参加 |

ReduceScatter 常和 AllGather 配成一对，用来代替一次 AllReduce，并顺便把序列维或隐藏维摊到各卡。Send/Recv 是流水并行把隐藏向量交给下一张卡时用的。

### 12.5 哪种部署用哪种通信

| 部署 | 切什么 | 推理时的通信 | 网络 |
|---|---|---|---|
| DP | 切请求 | 副本之间不通信 | 可以不连 |
| TP | 切一层的权重 | 每层 AllReduce，或 ReduceScatter + AllGather | 组内均匀的 scale-up |
| PP | 切层 | 相邻卡 Send/Recv 隐藏向量 | 连成链即可 |
| EP | 切专家 | 每层两次 All-to-All（送出去、再送回来） | 全体两两都要快 |

训练时 DP 还要做梯度 AllReduce；PP 反向再 Send/Recv 一次。TP、EP 在反向时再做一遍与正向对应的集合通信。

**Scale-up** 是一个节点或一个机柜里的专用高速互联（NVLink、C2C 背板），延迟低，一层算完就要用到对面卡的结果。**Scale-out** 是节点之间的 InfiniBand 或以太网，带宽小得多，适合 DP 这种偶尔同步一次。A2A 要求参加的卡在 scale-up 上全互联：任意两张卡都有路，而且最好一样快。两组四卡、组间只有更窄的 CDFP 时，跨组的那一份会把整次 All-to-All 拖慢。

## 13. Kernel、Stream、Send/Recv

**Kernel** 是一次下发给 GPU 的函数，例如一次矩阵乘或一次把数据发到对面卡。下发之后，芯片上的很多线程一起跑完，这个 kernel 才结束。

**Stream** 是一条队列。同一个 stream 里的 kernel 按提交顺序执行。能开多条 stream 的 GPU，可以让计算和通信排在不同队列里：通信在等对方时，计算队列还能跑。

Send/Recv 在两边各是一个 kernel。自己这边下发了还不算完，对端也得下发匹配的那一次，数据传完，两边才一起结束。只有一边进入，这一边就停在 kernel 里等。

有的硬件同一时刻只有一条 stream、只能执行一个 kernel。当前 kernel 不结束，下一个就不能开始，计算和通信也不能重叠。这时如果两张卡的提交顺序不一致，就会 hang：

```text
卡 A：矩阵乘 → sendrecv
卡 B：sendrecv → 矩阵乘
```

卡 B 先占住唯一的 kernel 名额，停在 sendrecv 里等卡 A。卡 A 还在矩阵乘，进不了 sendrecv。若这次矩阵乘又要等卡 B 先把数据送来，两边就一直互等。所以这种机器上，所有卡必须按同一顺序提交通信和计算。

## 14. 精度

比特数决定一个数占多少字节，也决定从显存搬权重有多慢。范围和小数位数不能同时都大。

| 格式 | 比特 | 常见用途 |
|---|---|---|
| FP32 | 32 | 累加、softmax、一部分归一化 |
| BF16 | 16 | 范围接近 FP32，小数较粗。训练和未量化推理的默认浮点 |
| FP16 | 16 | 小数比 BF16 细一点，范围小，容易溢出 |
| FP8 | 8 | H100 及以后。推理权重、激活常用 E4M3 |
| INT8 | 8 | 整数加 scale。可以只量化权重，或权重和激活一起量化 |
| INT4 / FP4 / NF4 | 4 | 主要压权重，把显存留给 KV cache 或更大的模型 |

语言模型训练多用 BF16 混合精度，求和和优化器状态仍可能是 FP32。推理视显存而定：放得下就用 BF16/FP16；数据中心常见 FP8；再省就用 INT4/FP4 存权重，计算时还原或直接走低精度 Tensor Core。KV cache 默认跟着 BF16/FP16，上下文很长时再压成 FP8 或 INT8。

文生图、文生视频的去噪网络训练也是 BF16/FP16，推理长期以 BF16/FP16 为主。同一步的误差会留在 $z$ 里，走很多步之后，INT4 容易出现色块和发糊。大 DiT、视频模型用 FP8 已经比较常见。

VAE 很小，一般是 FP32 或 BF16/FP16，很少做 INT8/INT4。旧版 Stable Diffusion 的 VAE 在 FP16 下会花屏，解码常用 FP32，或换修过数值的 FP16 版本。它不是带宽大头，不值得用画质去换那点显存。

适合量化的是大矩阵：注意力的 $W_Q$ 到 $W_O$，FFN 和 MoE 专家，DiT / U-Net 的线性层和卷积（优先 FP8）。通常仍留在 BF16 或 FP32 的是 RMSNorm、softmax 前后的累加、RoPE、很小的路由器，以及 VAE 解码器。嵌入和 `lm_head` 可以压，但比中间层容易伤到用词。没有对应内核，或压完质量不能用，工程上就当作不能量化。

## 15. 矩阵乘和卷积

语言模型一层里的大头是 GEMM：`W_Q`、`W_K`、`W_V`、`W_O`，注意力的 $qk$ 和 $pv$，以及 FFN 的三套矩阵。RMSNorm、残差、SiLU、RoPE、嵌入查表都有，耗时通常远小于这些矩阵乘。主干里基本没有卷积。

文生图、文生视频按段分：

| 部分 | 主要算子 |
|---|---|
| 文本编码器 | 矩阵乘和注意力 |
| DiT 去噪 | 矩阵乘和双向注意力，外加把隐图像切成 patch 的线性层 |
| VAE | 卷积。编码缩小像素，解码再放大 |
| 老的 U-Net 去噪 | 卷积是主干，注意力只插在一部分层 |

卷积用一小块核在图上滑动，整张图共用这套核，用来找局部的边缘和纹理。核大小、步长、填充、输出通道决定输出图的高宽和厚度。步长为 2 时高宽大约减半，VAE 和 U-Net 靠这个下采样。$1\times1$ 卷积不看邻居，只混合每个像素自己的通道。

## 16. 卡内带宽和卡间带宽

HBM 是一张 GPU 自己的显存，和芯片做在同一块封装上。显存带宽是芯片和 HBM 之间能搬多快。权重、KV cache、激活都在这里。算的时候再经 L2、SM 上的缓存进寄存器。寄存器只是正在乘的那一小块的工作台，装不下整层的 K、V。语言模型 decode 偏带宽，是因为同一份 HBM 里的权重和 KV cache 只服务一个（或很少几个）新 token。

NVLink 不经过这颗 HBM。它是 GPU 芯片之间的链路。张量并行的 AllReduce、专家并行的 All-to-All 走它。没有 NVLink 时，卡间只能走 PCIe。

NUMA 是另一层远近：双路服务器上每颗 CPU 有自己的内存条。跑在 CPU0 上的程序读 CPU0 的内存是近的，读 CPU1 的内存要穿过两颗 CPU 之间的总线。插在某一颗 CPU 的 PCIe 上的 GPU，用这边的内存传数据也更近。`numactl` 和 `nvidia-smi topo -m` 看的就是这个划分。SXM 上 GPU 之间走 NVLink，不经过这段；CPU 读写 GPU 仍然落在某个 NUMA 节点上。

## 17. PCIe、CDFP、NVLink

CDFP 是 PCIe 外接线的连接器，不是 NVLink 的插头。一个口按早期 400G 规格大约单方向 50 GB/s；当作 PCIe Gen5 x16 时，双向大约 128 GB/s。一根 NVLink 4 双向大约 50 GB/s，一个 CDFP 口可以比一根 NVLink 粗。一张 H100 有 18 根 NVLink，整卡双向 900 GB/s；Blackwell 整卡大约 1.8 TB/s。两张卡用一根 CDFP 相连，带宽是 PCIe 那一档；用 NVLink 桥或 NVSwitch 相连，是多根 NVLink 加在一起，比一根 CDFP 高得多。

PCIe 卡各自插在主板槽上。多张卡通信是「GPU → PCIe switch 或 CPU → 另一张 GPU」，是一棵树，不是两两各拉一根专用线。RTX PRO 5000、RTX PRO 6000（Blackwell，含服务器版）没有 NVLink，系统接口只有 PCIe 5.0 x16。Ada 的 RTX 5000 / 6000 也没有。再往前的 RTX A6000 才有双卡 NVLink 桥。

SXM 不插 PCIe 槽。八卡 HGX H100 把 8 个模组和 4 颗 NVSwitch 放在同一块底板上，每张卡的 NVLink 全部进 Switch。任意两张卡走同一套网，卡 0 到卡 1 和卡 0 到卡 7 带宽相同。四卡可以不放 Switch，在背板上两两直接连。八卡若两两焊死，18 根线要分给 7 个邻居，每对只有大约两根，而且不能把全部 900 GB/s 临时给其中一张卡。Switch 是无阻塞的：线都接到交换芯片上，这一次把带宽配给正在通信的那几张卡。卡再多，口数不够连到所有其他卡，只能继续接到 Switch 上。

两组四卡、组内走背板、组间走 CDFP 的八卡机，组内可以很宽，跨组窄在线缆上。这和 HGX 八卡不是同一种拓扑。H100 要把两个四卡 NVLink 域合成一个，用的是外部 NVLink Switch 和 OSFP 线，不是 CDFP。不接这套交换机时，两个域之间只剩 PCIe 或网卡。
